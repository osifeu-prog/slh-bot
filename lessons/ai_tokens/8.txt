תוכן שחוזר על עצמו הוא בזבוז פוטנציאלי — ולכן caching הוא כלי מרכזי במערכות AI.

בפועל, ספקי מודלים מציעים כיום מנגנוני prompt/context caching בתנאים שונים, והמחירים והספים משתנים. בדקו תמיד את התיעוד הרשמי של הספק לפני אופטימיזציה כספית. לדוגמה, Google מפרסמת מחירי context caching נפרדים לפי מודל ורמת שירות.

### לחשוב כמו blockchain
חלק קבוע אפשר לראות כ"prefix" יציב:
- system rules
- tool definitions
- project context
- מסמכי ידע יציבים

וחלק משתנה:
- user message
- current state
- new evidence

כך מתקבלת צורת עבודה:

STABLE CONTEXT
↓
CACHED / REUSED
↓
CURRENT EVENT
↓
NEW RESPONSE

היתרון הוא לא רק מחיר.
גם ארכיטקטורה טובה יותר נוצרת:
- פחות payload חוזר
- פחות רעש
- פחות סיכון לסתירות
- יותר הפרדה בין "מה קבוע" לבין "מה השתנה"

### אבל cache אינו truth
Cache יכול להיות ישן.

לכן:
Canonical State / Live Runtime > Cached Context

זה כלל קריטי במערכות שיש בהן כסף, הרשאות או מצב מערכת.
