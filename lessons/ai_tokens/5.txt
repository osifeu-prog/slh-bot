היסטוריית שיחה היא גם מקור עלות וגם מקור הקשר.

אם שולחים שוב ושוב את כל ההיסטוריה, כמות טוקני הקלט מצטברת במהירות. לכן מערכות AI טובות אינן רק "זוכרות" — הן מנהלות זיכרון.

### זיכרון בסגנון ledger
אפשר להסתכל על כל turn כרשומה:

timestamp
+ user message
+ assistant response
+ topic/intent
+ relevant state

ואז לבנות:
Recent History → Summary → Current State

במקום לשמור כל דבר בלי סוף, שומרים שכבות:
1. כמה turns אחרונים לקרבה מיידית
2. summary לנושאים ישנים
3. state מובנה עבור עובדות חשובות
4. ראיות/אירועים שאפשר לחזור אליהם

### למה זה מזכיר בלוקצ׳יין?
הדמיון אינו בכך שהשיחה הופכת לבלוקצ׳יין.
הדמיון הוא במשמעת:
- אירועים נרשמים לפי סדר
- כל state מגיע מקודם
- אפשר להסביר כיצד הגענו לכאן
- לא משנים את ההיסטוריה כדי "לסדר" תשובה בדיעבד

### כלל "המשך"
כאשר המשתמש אומר:
"כן"
"המשך"
"תמשיך"
"continue"

המערכת צריכה:
1. למצוא את הנושא האחרון
2. לקרוא את ה-context האחרון
3. להמשיך מאותה נקודה
4. לא להתחיל מחדש
5. לא להפוך את ה"כן" להרשאה לפעולה

זה מאפשר שיחה טבעית יותר, זולה יותר, ועקבית יותר.
